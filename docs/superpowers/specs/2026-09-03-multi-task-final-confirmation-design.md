# 得物自动报名：多任务演练与真实最终确认设计

## 目标

将现有单次人工闸门改为本轮运行级别的最终确认授权，使同一个 APK 可以连续验证多个任务，也可以在用户明确授权后连续完成真实报名。

未授权时，自动化仍走完列表筛选、详情复筛和报名信息填写，在“报名后无法取消”的最终弹窗停留并记录结果，然后取消并返回商单列表继续下一项。授权后，自动化才允许点击最终确认，并以明确成功页面计数。

## 前台交互

删除以下旧控件：

- “单次实测模式”复选框；
- “任务报名后无法取消”复选框；
- 到达最终弹窗后才显示的旧“允许本次最终确认”面板和按钮。

首页在开始按钮之前常驻一个最终确认按钮。它有两个清晰状态：

- `最终确认报名：未开启`：默认状态，执行多任务演练，不完成真实报名；
- `最终确认报名：已开启（仅本轮）`：允许本轮对符合条件的任务执行真实最终确认。

按钮在任务开始前可以点击切换。任务运行期间按钮锁定，不能中途改变本轮模式。停止任务、运行完成、发生错误、无障碍服务重建或应用重新启动后，授权自动失效并恢复为“未开启”。授权状态不写入 SharedPreferences，不随 APK 升级或进程重启保留。

“目标报名成功次数”改名为“目标处理任务数”，范围继续限制为 1 至 20：

- 演练模式按成功到达标准最终弹窗并安全取消的任务数计算；
- 真实模式按检测到明确报名成功页面的任务数计算。

## 配置与运行快照

`AutomationConfig` 使用本轮最终确认授权字段替代单次实测字段。前台点击开始时读取按钮状态，并与类目、奖励范围、屏蔽词、目标任务数等配置一起生成不可变的本轮快照。

控制器不得在运行中重新读取按钮状态。这样可以保证用户切换应用、系统重建 Activity 或前台界面刷新时，不会意外改变已经开始的运行模式。

## 演练模式流程

每个候选任务依次执行：

1. 完成列表奖励与标题筛选；
2. 打开详情，检查商品名字、合作方式、达人要求；
3. 打开报名信息页，验证地址并填写样品规格；
4. 点击报名信息页的“确认报名”，进入标准“报名须知/报名后无法取消”弹窗；
5. 确认最终弹窗、当前运行编号和当前任务签名均正确；
6. 在弹窗停留约 2 秒，记录“演练通过，未报名”；
7. 只点击精确文字“取消”；若取消按钮不可用，则执行一次系统返回；
8. 验证不可撤销弹窗已经消失，再逐级返回商单列表；
9. 演练通过数加一，当前任务标记为“已演练，未报名”，继续下滑查找下一项。

演练模式任何路径都不得点击最终弹窗的“确认”。仅当安全取消成功且回到商单列表时，才继续处理下一个任务。达到目标处理任务数后停止。

## 真实报名模式流程

真实模式在到达同一标准最终弹窗后执行：

1. 校验当前运行授权仍有效；
2. 校验当前任务签名存在，且本轮没有对该签名执行过最终确认；
3. 获取当前任务的一次性确认锁；
4. 只点击最终弹窗底部精确文字“确认”的可见按钮一次；
5. 进入结果验证状态，不再对该任务点击确认；
6. 只有检测到“已报名，待品牌方确认”或已确认的等价成功标志，才把真实成功数加一；
7. 返回商单列表，继续扫描下一任务；
8. 真实成功数达到目标处理任务数后停止。

若最终确认后结果不明确，立即停止整个运行，报告“结果未知”，不得重试该任务或继续下一个任务。

## 多任务确认保护

现有 `SingleEnrollmentGate` 的“整轮只允许一次”限制不再适用。新的最终确认保护按“运行编号 + 任务签名”控制：

- 同一任务在一轮中最多点击一次最终确认；
- 不同任务可以分别获得一次确认机会；
- 已确认、结果未知或已演练的任务签名加入本轮集合，重新出现在列表时跳过；
- 切换运行编号会清空内存中的任务级锁，但不会恢复已经发生的平台报名；列表中的“已报名”状态仍必须被识别并跳过。

## 计数与界面状态

运行时分别维护：

- 已扫描；
- 符合筛选；
- 已跳过；
- 演练通过；
- 真实报名成功；
- 最终确认点击次数。

主状态文字显示当前模式和进度，例如：

- `演练模式 · 已验证 2/5 · 未产生报名`；
- `真实报名 · 已成功 2/5`。

扫描结果中的任务状态区分“未报名”“已演练，未报名”“报名成功”“结果未知”。不得把演练通过计入真实报名成功数。

## 返回与继续策略

演练取消或真实报名成功后，共用现有返回商单列表状态：

1. 先识别当前是否已经在商单页；
2. 若仍在报名信息或任务详情页，逐级返回，最多四次；
3. 回到商单页后清理当前任务上下文，进入列表下滑状态；
4. 当前排序达到最大下滑次数后按既有规则切换排序、返回首页浏览并开始下一轮；
5. 模式对应的完成计数达到目标后直接结束，不再进入下一个任务。

## 错误处理与安全边界

- 最终确认按钮默认关闭，真实授权永不持久化。
- 仅在标准不可撤销弹窗同时包含“报名须知”和“报名后无法取消”时处理取消或确认。
- 演练模式找不到安全取消路径时停止，不点击其他按钮猜测返回。
- 真实模式最终确认后结果未知时停止，不自动重试。
- 验证码、人机验证、申请入驻和未知弹窗继续按现有规则停止。
- 目标处理任务数只统计演练通过或明确报名成功；详情排除、表单失败和返回失败不计数。

## 测试设计

### 离线测试

1. 最终确认授权默认关闭且不从偏好恢复。
2. 演练模式到达最终弹窗时产生取消决策，绝不产生确认决策。
3. 真实模式对一个任务只产生一次确认决策。
4. 同一运行中的第二个不同任务可以获得独立确认锁。
5. 同一任务重复出现时被拒绝再次确认。
6. 演练计数与真实成功计数互不混用。
7. 两种模式都在各自计数达到目标时停止。
8. 结果未知时停止且不生成第二次确认。

### 真机测试

阶段一使用演练模式，目标处理任务数至少为 2。两个任务都必须到达最终弹窗、自动取消、返回商单并继续，全程真实报名成功数和最终确认点击数均为 0。

阶段二只有在用户再次明确授权真实测试时执行。开启“最终确认报名”后，设置用户允许的真实报名目标数，验证每个任务只确认一次、成功后返回商单继续，并在达到目标后停止。

## 验收标准

1. 首页安全控制只保留一个常驻“最终确认报名”按钮，默认未开启。
2. 未开启时可以连续演练多个任务，每项到最终弹窗后取消并继续，不产生真实报名。
3. 开启后可以对不同任务分别完成一次真实最终确认。
4. 达到目标处理任务数后自动停止。
5. 停止、错误或重启后真实授权自动清除。
6. 同一任务不会重复点击最终确认，结果未知时不会继续运行。

## 非目标

- 不绕过验证码、平台风控或账号限制。
- 不自动开启真实最终确认。
- 不保存真实报名授权供下次运行使用。
- 不改变产品类目、奖励范围和三字段屏蔽词规则。
