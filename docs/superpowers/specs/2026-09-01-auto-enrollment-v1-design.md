# 得物自动报名无障碍版 V1 设计规格

日期：2026-09-01

## 1. 目标与范围

V1 将当前只读筛选预演升级为可供测试者使用的自动报名工具。用户明确启动后，应用通过 Android 无障碍服务完成商单筛选、任务详情复核、报名确认、报名结果验证，以及首页作品浏览与下一轮商单循环。

V1 仅操作用户已登录的得物账号和公开可见页面，不调用得物私有接口，不绕过验证码、安全验证或平台风控。普通第三方应用没有强制停止得物的系统权限，因此“关闭得物”实现为软重置：连续返回到安全页面、回到系统主页并重新拉起得物；不得把它描述为真正的 `force-stop`。

## 2. 已验证的真实报名流程

达人号入口固定为：`我 → 商单`。当个人页存在“商单”快捷入口时，只允许使用该入口；入口不可点击时停止，不改走创作中心等其它路径。

一次真实配件报名已经验证，页面顺序如下：

1. 商单列表点击任务卡的“报名”。
2. 任务详情页读取任务信息、达人要求、发布要求与合作方式。
3. 点击底部“立即报名”。
4. “确认报名信息”页检查收货地址并填写样品规格，可选填写备注。
5. 点击“确认报名”。
6. 在“报名须知”不可撤销弹窗中点击“确认”。
7. 结果页出现“已报名，待品牌方确认”或等价成功文案。

确认成功后，本次成功数加一。应用返回商单列表，重新确认排序和类目状态，继续寻找下一项。达到 UI 设置的目标报名数后停止。

原始真机截图和无障碍树保存在本地构建目录 `app/build/outputs/apk/debug/signup-flow/`，其中可能包含账号地址信息，不纳入 Git，也不在日志中输出。

## 3. 完整自动化循环

### 3.1 启动与导航

1. 读取并规范化 UI 参数。
2. 检测无障碍服务；未开启时不启动任务。
3. 获取屏幕分辨率，用于 WebView 可见节点的手势兜底。
4. 执行卡密验证并启动心跳；验证或心跳失败时停止。
5. 对得物执行软重置。
6. 使用包名 `com.shizhuang.duapp` 拉起得物。
7. 检测得物首页。
8. 点击“我/我的”。
9. 检测达人号个人中心。
10. 点击达人号“商单”快捷入口。
11. 检测商单列表页。

### 3.2 商单筛选与双阶段排序

12. 第一阶段固定选择“最近发布”。
13. 打开产品类目并选择 UI 配置的类目。WebView 未暴露可点击节点时，只能在已确认类目菜单打开后使用菜单行坐标兜底。
14. 扫描当前可见任务卡，读取标题、现金奖励、报名人数、名额、截止状态和报名入口。
15. 当前页没有合适任务时向下滚动，滚动次数由 UI 的“单阶段最大下滑次数”控制。
16. 第一阶段达到下滑次数后，重新打开排序菜单，选择 UI 的“第二阶段排序方式”。如果 UI 仍选择“最近发布”，允许重新选择相同项。
17. 第二阶段排序完成后将阶段下滑计数清零，继续扫描任务。
18. 报名成功后返回列表并继续下滑寻找更多任务；下滑次数仍受当前阶段 UI 上限控制。

### 3.3 首页作品浏览与下一轮

19. 两个排序阶段均完成且尚未达到目标报名数时，返回得物首页。
20. 在首页随机打开作品，数量由 UI 的“每轮首页作品数”控制；设置为 0 时跳过整个首页浏览阶段。
21. 识别作品类型：图文按 UI 的最小/最大次数随机左右滑动；视频在 UI 的最小/最大停留秒数内随机停留。无法识别类型时按视频停留策略处理，不进行盲目左右滑动。
22. 使用作品页可访问的返回节点或系统返回动作回到得物首页，并验证首页标志。
23. 再次执行 `我 → 个人中心 → 商单`，不使用其它入口。
24. 重新执行最近发布、UI 第二排序、产品类目、扫描、详情复核与报名动作。
25. 报名成功数达到 UI 设置的目标报名数后立即停止并展示结果。

## 4. 任务筛选规则

### 4.1 列表阶段

任务卡必须满足：

- 奖励金额可解析且处于 UI 最低价和最高价之间。
- 报名人数未达到总名额。
- 未出现“已截止、报名结束、不可报名”等停止标志。
- 标题未命中屏蔽词。
- 当前运行内没有处理过相同任务签名。

列表阶段只决定是否值得打开任务详情，不直接进入最终确认。

### 4.2 详情阶段

打开任务后，应用收集任务详情页可访问的完整文本，重点包括：

- 任务标题与标签。
- 发布形式、发布时间和发布要求。
- 合作方式、商品是否寄回、样品方式。
- 达人要求。
- 页面中的补充说明。

同一份 UI“屏蔽词”同时应用于列表标题和详情全文。默认屏蔽词在原有基础上增加出镜和视频类要求：

`内定, 复投, 直接报名, 订阅提醒, 定制, 露脸, 真人出镜, 出镜, 拍视频, 视频拍摄, 口播, 直播`

匹配规则忽略大小写和常见分隔符。详情全文命中任意屏蔽词时：记录“详情命中屏蔽词：X”，返回商单列表，将任务加入本次运行跳过集合，不点击“立即报名”。

## 5. 报名状态机

符合列表和详情规则的任务按以下状态推进：

1. `OPENING_TASK_DETAIL`：点击任务卡“报名”，等待任务详情。
2. `VALIDATING_TASK_DETAIL`：解析详情全文并执行二次屏蔽词检查。
3. `OPENING_ENROLLMENT_FORM`：点击“立即报名”。
4. `FILLING_ENROLLMENT_FORM`：检查默认地址；填写 UI 样品规格和可选备注。
5. `SUBMITTING_ENROLLMENT_FORM`：点击“确认报名”。
6. `CONFIRMING_IRREVERSIBLE_NOTICE`：确认弹窗包含“报名须知”和“报名后无法取消”等预期文案后，自动点击“确认”。
7. `VERIFYING_ENROLLMENT_RESULT`：等待“待确认、已报名、待品牌方确认”等成功标志。
8. `RETURNING_TO_TASK_LIST`：返回商单列表并验证筛选栏和任务卡标志。

不可撤销弹窗只有在任务详情校验、默认地址、样品规格和报名表单均通过后才允许自动确认。未知弹窗不得使用坐标猜测确认。

## 6. 报名表单规则

- 收货地址必须已存在且页面显示为已选择状态；地址缺失时停止整个运行，让用户处理。
- 样品规格使用 UI 配置值。UI 规格为空时，不猜测历史规格，跳过当前任务并记录原因。
- 当页面提供的可选规格与 UI 规格完全匹配时点击该选项；否则填写规格输入框。填写后必须重新读取页面，确认字段值一致。
- 备注默认为空；V1 不自动复制历史备注。后续可增加独立默认备注字段。
- “确认报名”按钮必须处于启用状态，否则返回并跳过当前任务。

## 7. 页面与参数设计

应用标题改为“得物自动报名 V1”。原“高级设置”改为“循环与执行设置”，并按实际用途分组。

### 常用筛选

- 产品类目。
- 第二阶段排序方式。
- 奖励范围。
- 屏蔽词，同时作用于标题与详情全文。
- 样品规格。

### 循环与执行设置

- 目标报名数：默认 1，范围 1–20。
- 单阶段最大下滑次数：默认 5。
- 页面刷新等待范围：默认 2–10 秒。
- 每轮首页作品数：默认 1，允许 0。
- 图文左右滑动次数范围：默认 1–8。
- 视频停留秒数范围：默认 5–10 秒。
- 轮次间休息分钟范围：保留，明确表示只在一轮商单与首页浏览均完成后使用。
- 卡密：放在最下方的授权区域，Debug 可为空，正式测试包按服务端配置决定。

主按钮改为“开始自动报名”，次按钮为“停止任务”。启动前展示不可撤销提示，并要求用户勾选“我了解报名后无法取消”。结果区展示：已扫描、符合、报名成功、报名失败/跳过、目标进度和最近任务原因。

## 8. 停止条件与恢复策略

以下情况立即停止整个运行：

- 用户点击停止。
- 达到目标报名数。
- 卡密失败或心跳失败。
- 验证码、安全验证、人机验证、滑块验证。
- 默认收货地址缺失。
- 达人号“商单”快捷入口不可用。
- 连续三次进入未知页面或无法返回商单列表。
- 达到全局动作安全上限。

以下情况仅跳过当前任务并继续：

- 标题或详情命中屏蔽词。
- 名额已满或任务截止。
- 奖励不在范围。
- 样品规格为空、不匹配或无法回读确认。
- “确认报名”按钮未启用。
- 详情页缺少预期任务标志。

运行时持久化本次已处理任务签名和成功计数，Activity 重建不会重复报名；应用进程完全退出后 V1 不自动恢复未完成的报名动作，必须由用户重新启动。

## 9. 组件边界

- `AutomationController`：只负责状态推进和页面导航，不直接实现文本解析细节。
- `TaskCardParser`：解析列表任务卡。
- `TaskDetailParser`：新增，抽取详情字段与完整可筛选文本。
- `TaskEligibilityEvaluator`：扩展为列表规则和详情规则两个入口。
- `EnrollmentFormHandler`：新增，处理地址检查、规格填写和表单启用状态。
- `AutomationRuntime`：记录阶段、报名成功数、跳过数、当前排序阶段、循环次数和最近结果。
- `DewuSelectors`：集中保存列表、详情、表单、不可撤销弹窗和成功状态文案。
- `MainActivity`：读取/保存配置并展示状态，不包含页面自动化逻辑。

## 10. 验证与发布门槛

### 离线测试

- 任务卡金额、人数、截止信息解析。
- 列表标题屏蔽词。
- 详情全文屏蔽词，包括露脸、视频、口播等样例。
- 样品规格匹配和空规格跳过。
- 目标报名数达到后停止。
- 同一任务签名不重复处理。

### 状态机测试

- 最近发布阶段 → UI 排序阶段。
- 报名成功 → 返回商单列表 → 下一任务。
- 两阶段无结果 → 首页浏览 → 再次进入商单。
- 未知弹窗不确认。
- 成功文案未出现时不累计报名数。

### 真机测试

- 先用目标数 1 完成一单。
- 再用测试账号验证目标数 2 的连续报名和返回列表。
- 验证首页作品数为 0 时完全跳过浏览。
- 验证命中详情屏蔽词时未进入报名表单。
- 验证安全验证页面会停止。

### UI 与构建

- Playwright 原型检查新执行设置、不可撤销确认和目标进度。
- Android `assembleDebug` 和 lint 通过。
- 测试 APK 显示 V1 版本号，并在 README 中注明真实报名不可取消及测试账号使用建议。

## 11. V1 不包含

- 验证码或安全验证绕过。
- 多账号并行报名。
- 得物私有 API 直接报名。
- 自动修改或新增收货地址。
- 自动付款、购买商品或支付押金。
- 进程被杀后的无人值守恢复。
